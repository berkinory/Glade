# Provider handoff context

Handoff creation imports the complete durable user/assistant transcript on the server, preserving the source workspace and recording an event boundary. Client hydration and client-provided imported messages do not choose the evidence. The original chat stays available. Original message identities are stored separately from imported display identities, including across repeated handoffs.

The destination provider and selected model prepare a versioned structured record using the existing authentication and process infrastructure. Preparation runs in a temporary empty workspace with task tools, skills, MCP servers and workspace instructions disabled. It does not start the continuation. Codex authentication routing is copied into an isolated home; Claude uses the authenticated SDK with settings sources disabled. Native default model selection remains native rather than substituting another model. Source-provider credentials, quota and runtime availability are not required.

The record distinguishes facts, proposals, attempted work, confirmed outcomes, failures and unknowns. Consequential factual claims require source references; constraints, scope changes, decisions, completed work and verification also require exact source passages. Unknown missing context and new proposals can lack references, but cannot masquerade as confirmed results. Quotes must match complete original paragraphs, log lines or an entire evidence entry. This proves attribution, not the semantic truth of a model's interpretation; inspect the actual diff and rerun relevant checks.

Large sources use coherent bounded segments and consolidation against selected original evidence. Consolidation keeps original quotes and the latest source user request; repeated handoffs also read original ancestor activities. A single indivisible oversized line or an oversized mandatory record returns an actionable error rather than prefix clipping. The final envelope includes the record, relevant complete turns that fit, the latest source user message verbatim, attachment references and retrieval instructions. A larger context window does not cause unrelated history to be added.

## Budget and accounting

Native runtimes do not expose a portable tokenizer or their entire system/tool prompt. The current conservative estimate counts UTF-8 bytes as tokens, applies a 20% context margin, and reserves 24,000 tokens for system/tools, 8,000 for output and 4,000 per new attachment. The new request is subtracted separately. Discovered context options are used when available; otherwise the assumed context is 64,000 tokens. These are estimates and reserves, not measured native prompt sizes. Independent transport character ceilings still apply.

Preparation passes use a separate bounded allowance because they have no task tools. Requests and completed results persist input identity, prompt identity, selected model, estimated/native usage and elapsed time. Rejected evidence is recorded with usage but never reused. Compatible successful passes and final records survive retry/restart. Failed native requests without usage make aggregate native totals unknown rather than zero. The final elapsed time covers the current preparation attempt; earlier pass timings remain in activities.

Do not claim total token or latency savings from the envelope size. A fair comparison includes every preparation attempt, target-turn usage, retrieval usage and elapsed time through the same useful continuation milestone. Cross-provider prompt caches are not assumed reusable.

## Retrieval and lifecycle

Existing `glade_read_thread` and `glade_read_thread_activity` accept `throughSequence` to read a frozen boundary. Thread retrieval retains existing cursor and lossless message pagination. Activity retrieval can select `activityId`, then follow `detailPage.keys`, `detailPath` and `nextOffsetChars` to read bounded original payload passages. Authorization stays with the existing gateway access rules; sensitive fields and embedded credentials are redacted before paging. Later source events are excluded, and missing/deleted source evidence fails explicitly. Attachment references and local paths do not preserve image content.

The destination shows preparation, ready, failure and cancellation. Retrying reuses completed passes and keeps the same destination and draft. Cancellation interrupts owned native work; stale preparation activity after restart can also be cleared. Context is marked delivered only after the native destination accepts the first turn. A failed first send retains pending bootstrap context. Existing provider session recovery remains a separate path.

Older handoffs without a frozen boundary preserve their transcript but require a fresh handoff from the original chat. No migration rewrites released schemas or stored history.
